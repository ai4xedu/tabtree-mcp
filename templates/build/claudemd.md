## The outline

This is the exact outline TabTree builds. Indentation is the hierarchy, and
`[ ]` marks a checkbox. You can paste it straight into TabTree, or into any
outliner that understands indentation.

```text
CLAUDE.md — project name
  What this is
    One sentence — what it does, and for whom
    The stack in one line — language, framework, storage
    Where the entry point is
  How to run it
    Start it — the exact command
    Run the tests — the exact command
    Build or lint — the exact command, or "none"
  Invariants — break these and it fails silently
    A value that must be updated in more than one place
    A boundary where untrusted input is checked
    A constraint that looks removable and is not
  Conventions
    Naming — files, functions, branches
    Comments — language, density, when one is warranted
    Commit messages — the shape you want
  Where things live
    Area 1 — the files that hold it
    Area 2 — the files that hold it
    Generated or vendored — never edit by hand
  What NOT to do
    Tools and dependencies that are off-limits, and why
    Refactors already tried and rejected
    Code that looks wrong and is deliberate
  Before claiming it works
    How a change is proven — the test, not the intention
    What to check in the real app, not only in tests
```
